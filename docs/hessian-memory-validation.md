# H100 Hessian 显存优化验证（2026-09-24）

最终版在41、62、78、111原子四个固定几何算例上均完成完整Hessian，原库在同一组请求上均曾OOM。显存目标得到验证；62原子的独立梯度差分仍未通过严格阈值，故策略保持实验性、默认关闭。

## 方法与范围

单张 H100 80GB，GPU4PySCF 1.8.1 / PySCF 2.8.0 / CuPy 13.6.0；实际张量收缩后端为 CuPy。固定几何，B3LYP-D3BJ/def2-SVP，DF 辅助基 def2-universal-jkfit，气相，99×590 网格及 nwchem 剪枝。SCF 收敛阈值 1e-10 Eh、梯度阈值 1e-7、直接积分阈值 1e-14。保持梯度网格/辅助基响应及 Hessian 辅助基响应阶数 2、网格响应设置。

41 原子组：电荷 0、三重态；62/78/111 原子组：电荷 0、单重态。此次没有测试 100 原子组，也不是完整 TSOPT/IRC 路径重跑。

本次策略修改 Hessian 的分块和内存规划，未更换后端、减少网格、松弛收敛标准或关闭响应项。原始源码校验值和参数见 [策略说明](hessian-memory.md)。

“完整 Hessian”包括电子部分的解析 Hessian 与上游 D3BJ 实现的梯度差分贡献。日志明确提示 DFTD3 不提供解析 Hessian；本分支保留该实现，不把色散梯度差分算作额外 SCF。

## 固定几何完整 Hessian

| 原子数 | AO 基函数 | 原库 Hessian 失败前峰值 / GiB | 新策略 Hessian 峰值 / GiB | 新策略整次请求峰值 / GiB | Hessian / 秒 | 结果 |
|---:|---:|---:|---:|---:|---:|---|
| 41 | 447 | 77.54，OOM | 13.32 | 15.15（梯度） | 155.99 | 最终版完成 |
| 62 | 709 | 76.47，OOM | 26.04 | 44.67（梯度） | 328.62 | 最终版完成 |
| 78 | 843 | 76.06，OOM | 40.81 | 52.03（梯度） | 594.55 | 最终版完成 |
| 111 | 1129 | 70.94，OOM | 77.13 | 77.13（Hessian） | 1657.67 | 最终版完成 |

峰值来自约 20 ms 间隔的 NVML 采样，按阶段时间戳划分，单位 GiB，包含设备上下文/缓存，可能漏掉极短峰值。Hessian 峰值与整次请求（SCF＋梯度＋Hessian）的峰值分别报告。旧 OOM 行的峰值是失败前已占用量，不包含分配失败的申请量，不能视为完成计算所需显存。

基函数数目采用分子对象的 `nao_nr()`；GPU 内部积分处理可能使用更多 Cartesian/分段基函数，不能仅凭表中 AO 数按固定每基函数内存比例外推。

111原子的新峰值高于原库失败前的峰值，因为原库没有走完后续阶段；优化的结果是完整计算能够完成，并不代表所有阶段的峰值都下降。77.13 GiB仍接近这张H100的可用容量，不能把此结果解释为已经有很大的显存余量。整次请求耗时依次为215.05、352.03、624.91、1716.81秒，不含进程/GPU库初始化。

新旧任务的镜像和科学参数相同，但不是同一物理 GPU 上交错重复的速度基准。失败基线没有完整 Hessian 时间；这里不定义相对失败基线的“加速比”。小体系首次运行还包含即时编译/缓存开销，不能把 off→conservative 的冷暖差异解释成加速。

## 数值与接口验证

- 水分子（最终版）：策略关闭/开启的 Hessian 最大元素差 8.020e-12 Eh/Bohr²；梯度差 4.441e-16 Eh/Bohr；能量差 0。
- 三重态 O2（最终版）：Hessian 最大元素差 1.762e-12 Eh/Bohr²；梯度差 1.421e-14 Eh/Bohr；能量差 0。小体系采用 16/8/8 的 J/K 导数块上限、一阶有效势辅助批次32，主动覆盖小块及尾块。
- 41 原子第一版（仅 J/K 导数分块）与第二版（再限制 CPHF 响应批次）：Hessian 差 1.574e-9 Eh/Bohr²、梯度差 4.157e-8 Eh/Bohr、能量差 3.638e-12 Eh。每次独立重新收敛 SCF，微小差异也包含 SCF 数值重复性。
- 第三版新增一阶有效势分块后，与第二版相比：41 原子 Hessian 最大差 3.063e-9、62 原子 1.028e-9 Eh/Bohr²。两例的能量差均小于4e-12 Eh，梯度差均小于9e-8 Eh/Bohr。
- 78原子第三版/第二版Hessian最大差1.644e-9 Eh/Bohr²，能量差0、梯度差1.316e-7 Eh/Bohr。111原子没有未修改版本的完整Hessian可对照，不能宣称做过该体系的完整基线数值比较；最终原始Hessian最大非对称误差为1.579e-10 Eh/Bohr²。
- 接口单元测试：13 项通过；wheel 构建通过。

- Gaussian External：水分子 off/conservative 的三个频率在输出精度内均为 1599.4360、3904.2304、4009.9445 cm⁻¹。conservative 频率计算之后，同一 worker 的 SP 和 OPT 均成功；SP 的导数阶数为 0、梯度/Hessian 时间为 0；OPT 的三个请求均为阶数 1、Hessian 时间为 0。
- 独立梯度差分没有全部通过，不能写作“所有数值验证通过”。水分子原库（off）在 0.002/0.001 Bohr 步长下最大误差 6.80e-7/8.75e-7 Eh/Bohr²，通过 1e-5 的检查阈值。
- 62 原子原 SCF 阈值、0.0005/0.00025 Bohr 步长：最大误差 2.016e-3/2.134e-3 Eh/Bohr²；另以 SCF 1e-11、轨道梯度 1e-9、0.002/0.001 Bohr 步长复查，误差降到 5.509e-4/6.870e-4，但仍未通过。收紧 SCF 不能消除该偏差；分块一致性与解析 Hessian 对梯度差分的一致性是两项不同的检验。

- 62 原子两组不同分块的完整 Hessian 均完成：默认 256/128/128、响应密度批次 8；对照 128/64/64、响应批次 4。最大 Hessian 差 2.395e-9 Eh/Bohr²、梯度差 9.892e-8 Eh/Bohr、能量差 3.638e-12 Eh，远小于上述梯度差分偏差。说明这些批次变化在本例中没有引入可见的大幅数值漂移，但不能替代独立的绝对精度验证。

差分偏差的具体原因仍待定位，不能仅凭当前结果归因于上游、网格或分块。本分支保持默认关闭，作为显存优化实验功能；未据此宣称大体系频率、TSOPT/IRC 已得到完整数值验收。

62 原子更小分块的 Hessian 为 394.93 秒、采样峰值 30.45 GiB；默认分块为 314.84 秒、29.93 GiB。它没有降低此例的整体 Hessian 峰值，因此没有选作默认。两次处于不同 GPU 作业，不能将这个时间差当作严格的跨节点速度基准。

## 失败定位与实现边界

第一版只限制 `rhf/uhf._jk_energy_per_atom`，41 原子完整 Hessian 成功，Hessian 采样峰值 57.47 GiB；62、78 原子仍在后续 CPHF 的 `rhf._get_jk` 张量收缩失败。第二版增加响应辅助块和密度批次数限制，验证的是完整 Hessian，而非仅最先触发 OOM 的收缩。

第二版的111原子算例在883.77秒后于`rhf._get_veff`构造一阶有效势时OOM，失败语句为`contract('pqr,qi->pri', ..., out=tmp)`。第三版将rhf/uhf两条一阶有效势路径纳入预算和分块策略，再做完整Hessian重测并成功。111原子的审计日志确认该阶段辅助积分批次由1232限制为256、积分子块由256限制为128，未修改上游安装文件。

CPHF网格诊断：已安装库默认辅助响应网格为50×194、sg1剪枝，而SCF主网格为99×590、nwchem剪枝。单独让62原子的CPHF使用主网格，Hessian最大变化2.973e-5 Eh/Bohr²；对收紧SCF后的梯度差分，误差仍为5.510e-4/6.882e-4。它没有解释主要偏差。这项网格替换只用于诊断，没有进入显存策略或改变生产配置。

另一个独立诊断在梯度差分计算中设置`mf.small_rho_cutoff=0`，关闭随密度变化的SCF网格筛除，仍得到5.372e-4/6.831e-4 Eh/Bohr²的误差，未通过阈值。这同样未改变生产配置。现有证据不支持把残余误差简单归咎于上述两个网格开关；后续需要单独审查梯度/解析Hessian的一致性。

测试镜像不能加载 `libcutensor.so.2`，所以未采用未经兼容验证的 cuTENSOR 替换。上游不同 lowmem 路径没有解决这里气相 DF Hessian 的两个工作区问题。本分支保留原安装包，通过明确启用且校验源码的作用域补丁实现。

## 复现工具与证据

`tools/hessian_suite.py RUN_ROOT` 在准备好的目录上逐一启动独立进程。根目录的 `cases.json` 为案例子目录名数组，每个案例需要：

- `config.json`：本项目解析后的 `gpu` 配置节，设置 `hessian_memory.policy`。
- `request.json`：`numbers`、`coords_bohr`、`charge`、`multiplicity`、`deriv: 2`。

套件生成 `summary.json`、每例 `result.json`、`derivatives.npz`、`nvml.jsonl`、`phases.jsonl`、后端诊断和 worker 日志。用 GPU Python 运行，设置本项目 `src` 到 PYTHONPATH，并提供与常规计算相同的 GPU 动态库环境。差分检查命令为：

```sh
python tools/hessian_finite_difference.py --case RUN_ROOT/g062_conservative --output NEW_FD_DIRECTORY --axis 3
```

中心差分步长为 0.0005、0.00025 Bohr，每个偏移点从中心已收敛密度重新投影初始化。它检查指定的一列，不代表对所有 Hessian 元素的独立验证。

加入`--steps .002 .001 --conv-tol 1e-11 --conv-tol-grad 1e-9`可复现收紧SCF的诊断。当前62原子的这两种差分检查均会保存结果并以非零退出码报告未达阈值；不要将平台失败状态误解为又一次OOM。

完整原始记录在私有、Git 忽略的运行目录：

- `runs/hessian_optimization_20260924T0155/`：第一版；后续终止以避免继续运行已知不完整策略。
- `runs/hessian_optimization_v2_20260924T0210/`：第二版固定几何测试。
- `runs/hessian_optimization_v3_20260924T0251/`：最终策略的小体系对照与111原子复测。
- `runs/hessian_optimization_v3_regression_20260924/`：最终策略的41/62/78原子回归。
- `runs/hessian_integration_20260924/`：Gaussian External 和中心差分。
- `runs/hessian_diagnostics_20260924/`：原库水分子差分、收紧阈值的大体系差分及另一组分块。
- `runs/hessian_cphf_grid_check_20260924/`：单独更换CPHF网格的诊断。
