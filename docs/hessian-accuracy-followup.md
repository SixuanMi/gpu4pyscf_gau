# Hessian 分块精度与 cuTENSOR 复核（2026-09-24）

结论：**已测62/78原子的显存分块不是原先导数偏差的来源**。完整原库对照把分块误差约束在 `1e-9 Eh/Bohr²`；主要偏差来自已审计版本DF梯度形成显式逆矩阵的算术路径。改为直接求解后，再收紧CPHF并使用SCF主网格，GPU内部一致性显著改善。具体启用方式见[精度配置](gradient-hessian-consistency.md)。

> 默认值更新：本记录中的“默认CPHF”指原测试基线（1e-6＋SG1），不是后续接口的新默认值。当前YAML示例及配置缺省值已按用户要求调整为1e-10＋SCF主网格；仍可显式恢复旧设置。

本次把两项验收分开：

1. **工程改动误差**：固定几何和同一组已收敛轨道，比较未修改的完整解析 Hessian 与 conservative 分块结果；不能用两个分块版本相互吻合替代这个对照。
2. **导数一致性**：比较解析 Hessian 与独立、重新收敛 SCF 后的梯度中心差分。当前检查阈值为最大元素差 `1e-5 Eh/Bohr²`；这是本轮诊断阈值，并非所有体系/软模态的统一质量保证。

此前独立差分超阈值的是 **62 原子**；78 原子此前只做过不同分块版本之间的比较。本次补充其原库对照和独立差分。

## 环境与控制变量

H100 80 GB，原镜像 GPU4PySCF 1.8.1、PySCF 2.8.0、CuPy 13.6.0 保持不变。只在私有运行目录安装 `cutensor-cu12==2.2.0`，通过子进程的 `LD_LIBRARY_PATH` / `PYTHONPATH` 暴露；没有覆盖原环境、安装文件或生产配置。

实测 CUDA Runtime API 为 `12090`（12.9），Driver API 为 `12080`（12.8）。原环境不能加载 `libcutensor.so.2`；隔离安装后 `cupyx.cutensor` 与底层扩展均成功导入，GPU4PySCF 的实际后端变为 cuTENSOR。双精度、带 `out` / 非零 beta 的收缩校验最大误差 `1.776e-15`，未使用混合精度。

仍使用 B3LYP-D3BJ / def2-SVP、DF def2-universal-jkfit、99×590 nwchem 网格及原响应项。为差分诊断，SCF 能量/轨道梯度阈值分别收紧至 `1e-11` / `1e-9`，上限200步。最初的分块对照保持Hessian CPHF原设置，实际 `conv_tol_cpscf=1e-6`；最终精度配置另列于下文。conservative 与 off 依次对**同一 MF 对象、同一组轨道**计算，不重新做 SCF；保存原始、未对称化矩阵。

## 同轨道的完整原库对照

| 体系 | conservative / off 最大差 (Eh/Bohr²) | RMS 差 | conservative / off Hessian 秒 |
|---|---:|---:|---:|
| 62 原子 / 709 AO | 2.04117e-9 | 1.42422e-11 | 234.06 / 195.83 |
| 78 原子 / 843 AO | 7.12959e-10 | 4.49912e-12 | 404.89 / 340.24 |

62、78 原子完整未修改 Hessian 均已成功完成；不再以另一个分块策略作为“原库基线”。分块引入的误差远小于 `1e-5`，不足以解释原先 `1e-4` 至 `1e-3` 的差分偏差。此结论限于受测体系、方法、版本和策略，不证明所有体系都具有相同精度。

对对称化后的笛卡尔力常数矩阵，62/78原子全部特征值的最大变化分别为 `7.954e-10` / `1.503e-10 Eh/Bohr²`；各自最负曲率特征向量的绝对重叠在12位小数内均为1。它检查分块对该方向的影响，不是质量加权频率分析，也不等于完成TSOPT轨迹验证。

时间仅为这次顺序对照的单次观测；存在运行顺序、缓存和节点差异，不作为独立的 cuTENSOR 加速比。原先没有 cuTENSOR 的 off 运行曾 OOM，本次该原库计算完成，表明配置收缩后端应先于评估是否仍需分块补丁。

## 修正及完整计算验收

第一步仅修改GPU DF梯度的度量矩阵作用次序，保留原分解方式、线性相关阈值和所有响应项：从 `C solve(J, C.T) B` 改为 `C solve(J, C.T B)`。两者在精确算术中等价，后者不形成显式逆矩阵。62原子原先第3列的偏差立即从约 `5e-4—7e-4` 降到约 `3e-6`；Hessian保持不变。因此它定位的是GPU梯度算术路径问题，而非通过改变Hessian迎合某个外部参考。对辅助度量条件数和具体舍入传播尚未逐项做误差界推导。

单独保留默认CPHF（阈值 `1e-6`、原辅助网格），只把梯度改为直接求解的已完成对照如下。误差取0.002/0.001 Bohr两个步长中的最大值，单位Eh/Bohr²：

| 体系/方向 | 只改直接求解 | 再收紧CPHF并使用主网格 |
|---|---:|---:|
| 62，第2个原子 x | 3.15e-6 | 2.77e-7 |
| 62，Ni x | 2.18e-5 | 2.33e-6 |
| 62，最负曲率方向 | 1.60e-5 | 1.29e-6 |
| 78，第2个原子 x | 7.10e-6 | 1.54e-6 |
| 78，最负曲率方向 | 7.02e-6 | 6.12e-7 |

62原子的第2个原子数据采用公开作用域补丁的差分报告；其参考Hessian仍为默认CPHF的分块矩阵（已证明分块与原库差异约1e-9）。其余初始方向对照使用同轨道未分块原库矩阵。两列对照均使用诊断用SCF阈值 `conv_tol=1e-11`、`conv_tol_grad=1e-9`，不能把“保留默认CPHF”误读为“所有生产参数均为旧默认值”。原接口SCF默认值仍是 `1e-10` / `1e-7`，没有自动更改。

第二步检查Ni x坐标和最负曲率方向。仅修正梯度时，62原子仍分别有约 `2.2e-5` 和 `1.6e-5` 偏差。只收紧 `conv_tol_cpscf` 到 `1e-10` 仍不足够；同时设置 `cphf_grid: scf`，让CPHF使用SCF的99×590主网格后通过。这里提高了响应积分和迭代精度，没有改变泛函、轨道基组、辅助基组或删减物理响应项。

最终使用仓库公开实现重新计算**完整** Hessian，而不以分项拼装结果作为最终验收。配置为 `df_gradient_metric=solve`、`conv_tol=1e-11`、`conv_tol_grad=1e-9`、`max_cycle=200`、`conv_tol_cpscf=1e-10`、`cphf_grid=scf`、`hessian_memory.policy=conservative`。各方向对正负位移重新收敛GPU SCF并计算GPU梯度。表内是 `max|H u − [g(R+hu)−g(R−hu)]/(2h)|`，单位Eh/Bohr²。

| 体系 | 方向 | h=0.002 Bohr | h=0.001 Bohr |
|---|---|---:|---:|
| 62 | C x，第2个原子 | 2.47193e-7 | 2.77296e-7 |
| 62 | Ni x，第49个原子 | 2.32995e-6 | 6.17574e-7 |
| 62 | 最负曲率方向 | 1.28639e-6 | 3.29013e-7 |
| 78 | 第2个原子 x | 1.53794e-6 | 4.32095e-7 |
| 78 | Ni x，第26个原子 | 6.68831e-7 | 2.72682e-7 |
| 78 | 最负曲率方向 | 2.71473e-7 | 6.12246e-7 |

两体系各3个方向、2个步长全部低于 `1e-5`；62/78原子的最大偏差分别为 `2.32995e-6 / 1.53794e-6`。两个最终作业均成功结束，78原子的金属方向独立差分报告也为 `passed: true`。

最负曲率方向取自原始对照Hessian的对称化笛卡尔矩阵，不是质量加权振动模态；保持固定方向用于前后比较。62原子最终完整Hessian与此前为定位原因而重算CPHF响应后拼装的矩阵最大差 `2.062e-9`，证实结论在实际完整调用中成立。

本次完整计算的SCF/梯度/Hessian单次墙时间分别为：62原子 `40.05 / 5.75 / 326.18 s`，78原子 `50.42 / 7.69 / 576.69 s`。提高响应精度有额外成本；不应拿新高精度Hessian与旧默认参数直接计算“工程加速比”。B3LYP电子部分采用解析Hessian；D3BJ沿用上游的色散Hessian差分实现，没有替换它。

验收范围是这些指定方向、两个步长和已审计闭壳层体系，不是全矩阵逐列差分，也不是新参数下完整TSOPT/IRC轨迹验证。41原子开壳层尚未验证，`solve`选项明确拒绝开壳层梯度；100/111原子未完成本轮精度验收。不要求CPU软件的绝对值一致。

公共实现还通过水分子SP、梯度和二阶导数请求回归：SP不算梯度/Hessian，梯度请求不算Hessian，作用域退出后上游函数恢复；相对原实现的水分子梯度/Hessian最大变化分别约 `7.28e-12 / 6.98e-12`。16项轻量接口/配置测试通过，隔离构建生成有效的 `gpu4pyscf_gau-0.1.0` wheel。主节点系统setuptools过旧，关闭构建隔离会误生成UNKNOWN包；有效构建使用项目声明的setuptools>=61隔离环境。

## 已排查的因素

- 同一固定波函数、同一几何重复计算梯度：62原子中心及 ±0.002/±0.001 Bohr 五点的最大重复差不超过 `4.16e-13 Eh/Bohr`。
- 仅在梯度积分中把实际 `AO_THRESHOLD` 从 `1e-10` 收紧到 `1e-14`：五点的梯度最大变化不超过 `1.32e-12 Eh/Bohr`，对应差分偏差未消失。这不等于修改了 SCF 全部筛选阈值。
- 在SCF和梯度两阶段同时收紧AO筛选至 `1e-14`，62原子两个步长仍有 `5.54e-4 / 7.17e-4` 偏差，未解决问题。
- GPU 一电子/Pulay梯度与CPU PySCF同波函数结果的独立对照：上述五个几何点的最大差不超过 `1.40e-12 Eh/Bohr`；用CPU分项替换这一分项不足以解释差分偏差。
- 重新完整构建中心 Fock 后，实际轨道梯度范数为 `4.11635e-10`，能量相对已收敛值变化0，轨道能量最大变化 `2.84444e-10 Eh`。实际安装的 DF `get_veff` 本来就完整计算 J/K，不使用传入的增量历史；因此停止了无区分度的“强制完整重建”后续差分实验。
- 原先的独立诊断已排查仅切换 CPHF 主网格、仅关闭 SCF 小密度网格筛除；均不能解释主要偏差，详见[原验证记录](hessian-memory-validation.md)。SCF 和 CPHF 的收敛阈值彼此独立。

## cuTENSOR 版本选择

cuTENSOR 对此实现不是功能上的硬依赖，缺失时可以回退到 CuPy；但 [GPU4PySCF 官方安装说明](https://github.com/pyscf/gpu4pyscf#installation)强烈推荐配置，并提醒 CuPy/cuTENSOR 不能任意混配。官方列出的组合包括 CuPy 13.3.0 + cuTENSOR 2.0.2、CuPy 13.4.1 + cuTENSOR 2.2.0。

[cuTENSOR 2.2 官方支持表](https://docs.nvidia.com/cuda/cutensor/2.2.0/index.html)列出 CUDA 11.0、11.8、12.x，并包含 SM8.9 / SM9.0。因此本次无需升级到 CUDA 13；4090 和 H100 可以分别在兼容的 CUDA 12.x 环境测试。应同时核对驱动、实际加载的 runtime、CuPy wheel 和 cuTENSOR版本，不能把 `nvidia-smi` 的 CUDA 字段当成 Python 实际加载的 runtime。

本次保留 CuPy 13.6.0，并对隔离的 cuTENSOR 2.2.0 做实际计算验证；这不是对任意 13.6 环境的兼容承诺。参考 [CuPy 13.6 安装文档](https://docs.cupy.dev/en/v13.6.0/install.html)。

此已审计 GPU4PySCF 封装不接受 `CONTRACT_ENGINE=cutensor`。应确保动态库能导入，并取消强制的 `CONTRACT_ENGINE=cupy`；通过 `backend_diagnostics()` 确认实际后端，而不能只看 pip 是否安装成功。
